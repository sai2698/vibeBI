01
Project Overview & Goals
This blueprint describes a full-stack, enterprise-grade BI platform built for vibe coding — meaning every module is decomposed into AI-prompt-friendly units that can be scaffolded with an LLM step by step. The platform mirrors QlikSense / Superset UX using Apache ECharts, Tailwind CSS, and Lucide React icons, backed by a Python FastAPI service layer.
1.1  Core Objectives
Self-service analytics: business users build dashboards without writing SQL.
Line-of-Business (LOB) scoping: each LOB has its own dashboard catalogue and search space.
Deep chart customisation: font, color, axis, legend, tooltip fully editable per chart (QlikSense parity).
AI-assisted analytics: natural language to chart, smart summarisation, anomaly detection.
Automated delivery: scheduled data refreshes + email reports (inline body + attachment).
Full RBAC + Row Level Security across all data paths.
Data export: CSV, XLSX, JSON, PDF directly from any chart or table.

7.2  NL-to-SQL Implementation
# ai/nl_to_sql.py
SYSTEM_PROMPT = """
You are a SQL expert. Given a database schema and a plain-English question,
return ONLY a valid SQL SELECT query. No explanations, no markdown fences.
The query must be read-only. Use table alias for clarity.
Schema: {schema}
"""
async def nl_to_sql(prompt: str, dataset: Dataset, user: User) -> str:
    schema_ctx = build_schema_context(dataset)
    messages = [
        {"role":"system","content":SYSTEM_PROMPT.format(schema=schema_ctx)},
        {"role":"user","content": prompt}
    ]
    sql = await llm_provider.complete(messages)
    sql = apply_rls(sql, dataset.id, user)   # RLS always applied
    validate_readonly(sql)                    # block DDL/DML
    return sql

# tasks/refresh.py
@celery.task(bind=True, max_retries=3)
def refresh_dataset_cache(self, dataset_id: int):
    """Warms Redis cache for all charts using this dataset."""
    charts = get_charts_for_dataset(dataset_id)
    for chart in charts:
        sql  = build_query(chart)
        sql  = apply_rls_base_filters(sql, dataset_id)   # base filters only
        rows = execute_query(chart.dataset.datasource, sql)
        cache.set(fingerprint(sql), rows, ttl=3600)
@celery.task
def send_email_report(report_id: int):
    """Render charts, build HTML body, attach files, send email."""
    report = get_report(report_id)
    context = build_report_context(report)  # renders charts to PNG bytes
    send_email(report, context)

        subtype  = MessageType.html,

Users belong to one or more Lines of Business (LOBs). The platform's home screen and navigation are scoped to the user's LOBs. Search is both within-LOB (default) and cross-LOB (for admins and analysts).

Admin can access all LOBs; regular users see only their assigned LOBs.
10.2  Dashboard Search Architecture
PostgreSQL Full-Text Search
search_vector TSVECTOR column on dashboards table (see schema section 2.2).
Trigger keeps search_vector updated on title/description/tags changes.
Query: WHERE search_vector @@ plainto_tsquery('english', :q).
Results ranked by ts_rank_cd(search_vector, query).
Search Endpoint
# search/router.py
@router.get("/search/dashboards")
async def search_dashboards(
    q:      str = Query(..., min_length=1),
    lob_id: int | None = None,
    tags:   str | None = None,    # comma-separated
    limit:  int = 20,
    user    = Depends(get_current_user)
):
    lob_ids = get_user_lob_ids(user)  # scope to user's LOBs
    if lob_id and lob_id in lob_ids:
        lob_ids = [lob_id]
    results = await db_search(q, lob_ids, tags, limit)
    return {"results": results, "total": len(results)}

Vibe Coding Guide — Building with AI LLM
Vibe coding means each feature is implemented by prompting an AI coding assistant (Cursor, Copilot, Claude, etc.) with well-scoped, contextual prompts. This section gives you the exact prompting strategy and module order for building this BI platform with AI assistance.
13.1  Vibe Coding Principles
Prompt one module at a time — never ask for the whole app at once.
Always include: tech stack, file path, existing imports, expected input/output.
After each generation: test it, then commit before moving on.
Use TypeScript interfaces and Python Pydantic schemas first — they act as contracts the AI will implement against.
Paste your schema (DB tables, API response shapes) into every prompt that needs data.
Say "no external component libraries — use Tailwind CSS only" in every frontend prompt.
13.2  Prompt Templates by Module
Backend Endpoint Prompt
Stack: Python FastAPI, SQLAlchemy 2.0 async, Pydantic v2.
File: backend/app/charts/router.py
Task: Add GET /charts/{chart_id}/export endpoint.
Input: chart_id (path), fmt (query param: csv|xlsx|json).
Output: StreamingResponse with correct Content-Disposition header.
Use existing get_chart_data_internal() from charts/service.py.
Use exporter functions from query_engine/exporter.py.
Apply RLS: always call apply_rls(sql, dataset_id, current_user).
Return 403 if user lacks can_read permission on the chart.
Frontend Component Prompt
Stack: React 18, TypeScript, Tailwind CSS, Lucide React, TanStack Query.
File: src/components/export/ExportMenu.tsx
Task: Dropdown menu with 4 items: CSV, XLSX, PDF, PNG.
Props: chartId: number, chartRef: RefObject<EChartsReactCore>
CSV/XLSX/PDF: call downloadFile(url) from utils/download.ts.
PNG: call chartRef.current?.getEchartsInstance().getDataURL() then trigger download.
Use Lucide icons: FileDown, FileText, FileSpreadsheet, Image.
No antd, no shadcn. Pure Tailwind only. Dropdown opens on button click.
AI Feature Prompt
Stack: Python FastAPI, OpenAI SDK.
File: backend/app/ai/nl_to_sql.py
Task: async function nl_to_sql(prompt, dataset_id, user) -> str
Steps: 1) load dataset columns from DB, 2) build schema context string,
3) call OpenAI chat completions with system prompt + user question,
4) extract SQL from response, 5) call apply_rls(sql, dataset_id, user),
6) call validate_readonly(sql) — raise 400 if DDL/DML detected, 7) return sql.
Store prompt + result in ai_queries table for audit.

13.4  Copilot / Cursor Tips for This Project
Open the relevant schema file and router file in the same editor pane before prompting — the AI will use both as context.
For Tailwind: write one component first, then tell AI "match this style pattern for the new component".
For RLS: always end your prompt with "and make sure RLS is applied via apply_rls() before any query execution".
For ECharts: paste the relevant section of the ECharts option schema into your prompt for accurate option generation.
For Celery tasks: always include the task signature and the import of the celery_app instance in your prompt.
Use chain-of-thought: ask AI to outline steps first, then implement each step.
